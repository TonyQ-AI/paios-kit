# 新项目立项（会话大脑 + 登记卡 + SpecKit 环境）

按「生产级即第一天」的立场初始化项目：**先把会话大脑立起来，再谈功能。** 本 skill 解决两件事——让 AI 从第一行代码就按生产底线写（不做假 MVP），并让任何新会话裸开就能接上（不丢上下文）。

## 适用范围
- 仅用于「从零创建全新项目 / 新工程」这一时刻。
- 已有项目的日常迭代、修 bug、重构 → 不触发本 skill，按项目现状处理。
- 纯配置类 / 一次性调试（不落项目产物）→ 告知用户这不属于新项目立项，按现行规则直接干活或仅补登记卡。

## 步骤

### 0. 立项前先查两处（只查 + 报，不替用户决定）
按全局 `~/.zcode/AGENTS.md` 的「新项目启动规则」执行——**先本机、再开源**，只做「查」与「报」；报什么、怎么报以该规则为准，本节不复制，避免双份维护。

**本机查重怎么跑**：`python {{ZCODE_DIR}}\scripts\project-scan.py --query "<2-3 个能力关键词>"`（索引秒级可重建：`--build`；只打印命中摘要：项目 / 路径 / 用途 / 标签 / 状态 / 活跃 / git / 命中词）。
命中候选后再读**它自己的** `My_NOTE.md` 确认真实现、真在役——**别逐个项目读全文**（82 个项目四类文件全读约 876 KB）。

### 1. 收集输入（缺了就用 「（待填）」 占位，别卡住流程）
- **项目名**（必填）
- **用途一句话**（必填）
- **技术栈**（可选）
- **项目路径**（可选；默认 = 当前工作目录下新建 `项目名/`）
- **首个功能**（可选；默认「尚未立项」）

### 2. 建目录 + git init
- 路径含中文 / 空格 → 用 python `os.makedirs` + `subprocess.run(list)`，**不做字符串拼接**。
- `git init`：项目根目录。纯 ASCII 路径可 bash 直跑。
- 已是 git 仓库则跳过。

### 3. 跑规格环境 `$speckit-cn-init`
- 该 skill 会装 `.specify/` 模板，并往 AGENTS.md 写「开发流程约定（SpecKit-CN）」段。
- 项目里已有 `.specify/` 或 AGENTS.md 含「SpecKit-CN」→ 跳过，保持幂等。

### 4. 生成项目级 AGENTS.md「会话大脑」
- 用 **Write / Edit** 工具写，UTF-8，正文中文（**禁止** echo / heredoc / cat<<EOF）。
- 若 AGENTS.md 已存在（含 SpecKit 段）：保留原内容，**追加**下方「会话大脑模板」；若无则整文件写入。
- 四节标题（生产底线/当前功能与状态/决策记录/续接点）与 SpecKit 段的「Active Technologies / Recent Changes」不冲突，可共存。

### 5. 形态确认（写 spec 之前，硬门禁）
- 运行 `$confirm-vision` 的**形态确认模式**，产出 `previews/形态确认.html`（上半 = 交付形态契约；下半 = 关键界面预览，无界面项目画使用流程 / 命令示例）。
- 把候选形态与**代价**讲给用户（每种形态各自的打包与分发成本），**由用户选定**；确认后把结果填进项目 `AGENTS.md` 的【交付形态】节（替换占位）。
- **用户确认通过前不得进入 `$speckit-cn-specify`**；本项目此后不再自动生成预览（只有用户点名、或某切片改变交付形态 / 主界面结构时才重新确认）。
- 顺手做最省事的一步：**第一片就把打包命令跑通**（哪怕功能是空的）—— 打不通不算完成，这样不会再出现"做完才发现要打包"。

### 6. 生成 My_NOTE.md 登记卡
- 用 **Write** 工具写，UTF-8，模板见下方「登记卡模板」。
- 已存在 → 更新 用途 / 状态 / 更新时间 / 产物目录 / 会话 字段；未存在 → 创建。
- 保持 ≤40 行，只记稳定项目事实，不记流水。

### 7. 报告
- 输出：项目**绝对路径**、`AGENTS.md` 与 `My_NOTE.md` 完整路径、`.specify/` 是否已装、所有「（待填）」清单。
- 提醒：生产底线是硬标准；改任何既定决定必须补一条【决策记录】；每会话结束更新【当前功能与状态】、【续接点】。
- 后续：告诉用户直接在这个项目里说需求（或 `$speckit-cn-specify`）就进入规格驱动流程。

## 会话大脑模板（追加到项目 AGENTS.md）

```markdown
# <项目名> · 项目大脑（每次会话自动加载）

> 本文件是项目的「会话大脑」，新会话自动注入。开发前先看【生产底线】和【当前功能与状态】；改任何既定决定，必须补一条【决策记录】。每会话结束更新【当前功能与状态】和【续接点】。

## 生产底线（每个模块必须达标，违反即返工）
- 模块接口有类型契约：入参 / 出参 / 错误码明确，不裸传 dict
- 错误处理：禁止 bare except；不外抛内部异常；统一错误模型
- 结构化日志：关键路径必打，带 trace / request id
- 配置走环境变量 / 配置中心，不硬编码密钥与业务参数
- 依赖注入；模块间不直接 new、不反向依赖
- 每个任务交付 = 实现 + 测试 + lint / type 通过；无 NotImplemented / no-op / 假数据兜底
- 第一款功能就是生产级垂直切片（配置 + 日志 + DI + 错误处理 + 接口 + 测试），不做「先跑通再说」
- 形态确认门禁（立项时一次）：立项阶段、写第一份 spec **之前**，运行 `$confirm-vision` 的**形态确认模式**，产出一份 `previews/形态确认.html`（交付形态契约 + 关键界面预览）；用户确认通过前不得进入 `$speckit-cn-specify`。确认后契约写入下方【交付形态】节，后续切片以它为准
- 后续不再自动生成预览：只在两种情况下重新确认——① 用户点名；② 某切片改变交付形态或主界面结构（属重大变更）
- 切片交付自检：每个切片交付时核对交付物形态与【交付形态】一致；偏离必须补【决策记录】并回到形态确认
- 规格门禁（写代码前硬性前置）：写任何 `app/` 业务代码前，必须已有 `specs/<当前功能>/spec.md` + `plan.md` + `tasks.md`（由 `$speckit-cn-specify` / `plan` / `tasks` 生成），且 `$confirm-vision` 已确认通过。**即使已有现成需求 / 架构 / API / 测试文档，也必须用它们喂养 `$speckit-cn-specify` 生成 `spec.md`，不得拿文档直接替代并跳过流程。** 不满足即禁止写业务代码。
- 入口门禁：任何「开发 / 实现 / 把项目做出来」类请求，若项目尚无 `specs/`，一律不得直接写业务代码；应先完整立项（`$new-project` + `$speckit-cn-init`）→ `$speckit-cn-specify` → `plan` → `tasks` → `$confirm-vision` 全部完成后，才进入实现。
- 唯一信源：用户提供的现成需求 / 架构 / API / 测试文档只作为**输入原料**，须经 `$speckit-cn-specify` / `plan` / `tasks` **映射**进 `specs/` 产物；生成后 `specs/` 是唯一权威信源，原始文档不得作为写代码依据。
- 术语红线：禁止用「MVP / 最小可行产品 / 先跑通再说 / demo」框架；一律说「生产级增量切片 / 垂直切片」。每片切片都是生产级，不做 throwaway demo。

## 交付形态（立项时定，后续切片以它为准）
- 形态：<桌面 exe ｜ 本地 Web 服务 ｜ 静态站点 ｜ CLI 工具 ｜ 浏览器插件 ｜ 移动端 App ｜ 库/包（PyPI/npm）｜ 服务端部署 ｜ 其他：___>
- 启动方式：<双击 exe ｜ 打开 http://127.0.0.1:端口 ｜ 命令行 xxx ｜ 装插件 ｜ 双击 .bat>
- 运行环境：<Windows only ｜ 跨平台 ｜ 需装 Python/Node ｜ 免安装单文件>
- 数据落地：<本地文件/本地 DB（路径） ｜ 云端 ｜ 混合>
- 分发方式：<单文件 exe ｜ 安装包 ｜ 复制目录 ｜ 上传服务器 ｜ 发 PyPI/npm ｜ 私有仓库>
- 首片打包验证：<第一片就要打通的命令，如 `npm run tauri build` / `python -m build`> —— 打不通不算完成

## 当前功能与状态
- 当前功能：<第一个功能名 / 或「尚未立项」>
- 规格目录：`specs/<编号>-<功能名>/`（spec.md / plan.md / tasks.md）
- done：

```

## 登记卡模板（My_NOTE.md）

**模板唯一来源**：`{{ZCODE_DIR}}\templates\My_NOTE.md` —— 复制到项目根目录改名 `My_NOTE.md` 后填写（≤40 行，只记稳定项目事实，不记流水）。此处不再复制一份，避免双份维护。

## 本机执行约定（与全局 AGENTS.md 一致）
1. 涉及 PowerShell 一律套静默包装：`python {{ZCODE_DIR}}/scripts/silent.py powershell -NoProfile -ExecutionPolicy Bypass -File <脚本> [参数]`
2. 含中文 / 空格路径的命令 → `python subprocess.run(list)`，不做字符串拼接。
3. 产物文件（AGENTS.md / My_NOTE.md / .ps1）一律 Write / Edit 工具写入；.ps1 用纯 ASCII 或带 BOM。
4. Git 相关：访问 GitHub 直连不通时走本机代理（端口按本机代理配置）（`git -c http.proxy=... -c https.proxy=...`）。

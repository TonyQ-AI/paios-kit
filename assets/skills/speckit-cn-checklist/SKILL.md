> 适配自 [SpecKit-CN](https://github.com/chameleon-nexus/speckit-cn)（commit 0db9fa5）的 `claude/.claude/commands/测试清单.md`；主副本在 `{{ZCODE_DIR}}/speckit-cn`。

## 清单定位："需求的单元测试"

**核心概念**：清单是**需求写作的单元测试**——校验给定领域中需求的质量、清晰度与完备性。

**不是**验证/测试实现：
- ❌ 不是"验证按钮点击正常"
- ❌ 不是"测试错误处理生效"
- ❌ 不是"确认 API 返回 200"
- ❌ 不是检查代码/实现与 spec 是否一致

**而是**需求质量校验：
- ✅ "所有卡片类型都定义了视觉层级要求吗？"（完备性）
- ✅ "'醒目展示'是否用量化尺寸/位置澄清了？"（清晰度）
- ✅ "所有交互元素的悬停态要求一致吗？"（一致性）
- ✅ "键盘导航的无障碍要求定义了吗？"（覆盖面）
- ✅ "规格定义了 logo 加载失败时的兜底行为吗？"（边界）

**比喻**：如果规格是用中文写的代码，清单就是它的单元测试套件——测需求写得好不好，不测实现行不行。

## 用户输入

用户输入 = 触发消息中技能名之后的文字（上游 `$ARGUMENTS`），通常是清单主题（如"UX需求质量检查"）。非空时必须先考虑。

## 本机执行约定

- 运行 `.ps1` 一律套静默包装：`python {{ZCODE_DIR}}/scripts/silent.py powershell -NoProfile -ExecutionPolicy Bypass -File <脚本> [参数...]`
- 项目根缺 `.specify/` → 先执行 `$speckit-cn-init` 流程再继续。
- 清单文件用 Write/Edit 工具写入，UTF-8，**全部条目与类别标题中文**。

## Execution Steps

1. **Setup**：在项目根运行 `.specify/scripts/powershell/check-prerequisites.ps1 -Json`（只运行一次），解析 `FEATURE_DIR` 与 `AVAILABLE_DOCS`。

2. **澄清意图（动态）**：最多生成 3 个初始澄清问题（现编，不用固定目录）。必须：
   - 从用户措辞 + spec/plan/tasks 提取的信号生成
   - 只问会实质改变清单内容的信息
   - `$ARGUMENTS` 里已明确的逐题跳过
   - 精确优先于宽泛

   生成算法：
   1. 提取信号：领域关键词（auth、latency、UX、API）、风险指标（"关键"、"必须"、"合规"）、干系人提示（"QA"、"评审"、"安全团队"）、显式交付物（"a11y"、"回滚"、"契约"）
   2. 聚类成候选关注域（最多 4 个）按相关性排序
   3. 推断受众与时机（作者/评审/QA/发布）如未显式给出
   4. 检测缺失维度：范围广度、深度/严格度、风险侧重、排除边界、可度量验收标准
   5. 从这些原型出题：
      - 范围收窄（"要包含与 X/Y 的集成触点，还是限于本模块正确性？"）
      - 风险排序（"哪些潜在风险域必须设强制门禁项？"）
      - 深度校准（"轻量提交前自检清单，还是正式发布门禁？"）
      - 受众框定（"作者自用，还是 PR 评审同行用？"）
      - 边界排除（"这轮明确排除性能调优项？"）
      - 场景类缺口（"未见恢复流——回滚/部分失败路径在范围内吗？"）

   出题格式：给选项时用紧凑表格（Option | Candidate | Why It Matters），最多 A-E；自由作答更清晰则不用表格；不问用户已说过的内容；不确定就显式问"确认 X 是否在范围内"。

   无法交互时的默认值：深度=标准；受众=代码相关取评审（PR），否则作者；关注=相关性前 2 的聚类。

   输出问题（Q1/Q2/Q3）。回答后若仍有 ≥2 个场景类（Alternate / Exception / Recovery / 非功能域）不清，可再追 2 个定向问题（Q4/Q5，各附一行理由）。总数不超 5；用户拒绝追加则停。

3. **理解请求**：合并用户输入 + 澄清答案：
   - 得出清单主题（如 security、review、deploy、ux）
   - 固化用户点名的必含项
   - 关注域映射到类别骨架
   - 从 spec/plan/tasks 推断缺失上下文（不许编造）

4. **加载功能上下文**：读 `FEATURE_DIR` 下 spec.md（必需）、plan.md（如有）、tasks.md（如有）。
   **加载策略**：只读与关注域相关的部分，避免整文件倾倒；长章节先摘要成条目；渐进披露。

5. **生成检查清单**——"需求的单元测试"。**重要：全部中文**：
   - `FEATURE_DIR/checklists/` 不存在则创建
   - 文件名：按领域的短描述名（如 `ux.md`、`api.md`、`security.md`），格式 `[domain].md`；已存在则**追加**到既有文件
   - 条目从 CHK001 顺序编号
   - 每次运行产生新清单（不覆盖既有清单）

   **核心原则——测需求，不测实现**，每条必须评估需求本身的：
   - **完备性**：必要的需求都在吗？
   - **清晰度**：需求无歧义且具体吗？
   - **一致性**：需求相互对齐吗？
   - **可度量性**：需求可客观验证吗？
   - **覆盖面**：所有场景/边界都覆盖了吗？

   **类别结构**（按需求质量维度分组）：需求完备性 / 需求清晰度 / 需求一致性 / 验收标准质量 / 场景覆盖 / 边界覆盖 / 非功能需求（性能、安全、无障碍等是否写明）/ 依赖与假设 / 歧义与冲突

   **条目写法**：
   - 问题式提问，聚焦 spec/plan 里**写了（或没写）什么**
   - 方括号标注质量维度 [完备性/清晰度/一致性/…]
   - 引用章节 `[Spec §X.Y]`；检查缺失需求用 `[Gap]` 标记

   **示例**：
   - 完备性："所有 API 失败模式的错误处理要求都定义了吗？[Gap]"
   - 清晰度："'快速加载'是否量化为具体时间阈值？[清晰度, Spec §NFR-2]"
   - 一致性："导航要求在所有页面间对齐吗？[一致性, Spec §FR-10]"
   - 覆盖面："零数据场景（无内容）的需求定义了吗？[覆盖面, 边界]"
   - 可度量性："'平衡的视觉权重'可客观验证吗？[可度量性, Spec §FR-2]"

   **场景分类覆盖**：检查 Primary / Alternate / Exception / Recovery / 非功能 五类场景的需求是否完整、清晰、一致；缺失时问"是有意排除还是遗漏？[Gap]"；发生状态变更时含回滚："迁移失败的回滚要求定义了吗？[Gap]"

   **可追溯性**：≥80% 条目至少含一个追溯引用（`[Spec §X.Y]` 或 `[Gap]`/`[Ambiguity]`/`[Conflict]`/`[Assumption]`）；无编号体系则问"是否建立了需求与验收标准编号体系？[Traceability]"

   **内容收敛**：候选条目 > 40 按风险/影响取舍；近重复合并；>5 个低影响边界项合并为一条。

   **🚫 绝对禁止**（这是实现测试，不是需求测试）：
   - ❌ 任何以"验证/测试/确认/检查 + 实现行为"开头的条目
   - ❌ 引用代码执行、用户操作、系统行为
   - ❌ "显示正确""运行正常""符合预期""点击/跳转/渲染/加载/执行"
   - ❌ 测试用例、测试计划、QA 流程；实现细节（框架、API、算法）

   **✅ 必须模式**（测需求质量）：
   - ✅ "[需求类型] 是否为 [场景] 定义/写明/记录了？"
   - ✅ "[模糊词] 是否用量化/具体标准澄清了？"
   - ✅ "[A 章节] 与 [B 章节] 的需求是否一致？"
   - ✅ "[需求] 能否被客观度量/验证？"

6. **结构参照**：标题、元信息、类别标题、编号格式参照 `.specify/templates/checklist-template.md`。模板不可用时用：H1 标题 + 目的/日期元信息 + `##` 类别章节 + `- [ ] CHK### <条目>`（全局递增编号，从 CHK001 起）。

7. **报告**：输出清单完整路径与条目数，提醒每次运行生成新文件。摘要：选定的关注域、深度、受众/时机、并入的用户必含项。

## 示例清单类型

**UX 需求质量**（`ux.md`）：
- "视觉层级要求是否定义了可度量标准？[清晰度, Spec §FR-1]"
- "UI 元素数量与定位是否显式指定？[完备性, Spec §FR-1]"
- "交互态要求（hover/focus/active）是否一致定义？[一致性]"
- "图片加载失败的兜底行为定义了吗？[边界, Gap]"

**API 需求质量**（`api.md`）：
- "所有失败场景的错误响应格式都指定了吗？[完备性]"
- "限流要求是否量化了具体阈值？[清晰度]"
- "外部依赖的重试/超时要求定义了吗？[覆盖面, Gap]"

**性能需求质量**（`performance.md`）：
- "性能要求是否量化为具体指标？[清晰度]"
- "高负载下的降级要求定义了吗？[边界, Gap]"

**安全需求质量**（`security.md`）：
- "所有受保护资源的认证要求都指定了吗？[覆盖面]"
- "敏感信息的数据保护要求定义了吗？[完备性]"
- "威胁模型是否已记录且需求与之对齐？[Traceability]"
